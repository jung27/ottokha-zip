# 사진 로딩·화면 흐름 개선

수정일: 2026-09-12. 사용자의 최신 요청에 따라 기존 등기부 미니게임과 단계 재시작 기능을 제거했다. 이전 `scenario-qa.md`의 해당 기능 검증은 과거 기록이다.

## 사진 로딩

22개 장면 사진을 WebP로 변환하고 긴 변 1,600px·800px 사본을 만들었다. 원본은 그대로 보관한다. 브라우저는 화면 너비와 픽셀 밀도를 보고 적절한 사본을 선택한다.

| 구분 | 22장 합계 | 원본 대비 감소 |
| --- | ---: | ---: |
| 원본 JPG·PNG | 51,878,853바이트 | — |
| 큰 화면용 WebP | 3,604,598바이트 | 93.1% |
| 작은 화면용 WebP | 1,199,316바이트 | 97.7% |

큰 사본은 한 장당 약 75~362KB, 작은 사본은 28~99KB다. 두 크기를 모두 한꺼번에 내려받는 방식은 아니다. 실제 다운로드량은 이용 경로와 화면 크기에 따라 달라진다. 위 수치는 파일 크기 비교이며, 실제 네트워크 로딩 시간 감소율을 측정한 값은 아니다.

현재 사진에 높은 다운로드 우선순위를 주고, 현재 장면과 바로 다음 장면에 필요한 사진을 낮은 우선순위로 순서대로 준비한다. 사진이 준비되기 전의 빈 프레임을 줄이기 위한 기존 디코딩 캐시도 유지한다. 원본을 서비스 번들에 포함하지 않는다.

반응형 이미지와 사전 로딩은 [web.dev의 반응형 이미지 사전 로딩 안내](https://web.dev/articles/preload-responsive-images), 다운로드 우선순위는 [Fetch Priority 안내](https://web.dev/articles/fetch-priority)를 참고했다.

재생성: Python과 Pillow가 있는 환경에서 `python frontend/scripts/optimize-images.py`. 파일별 크기와 실제 치수는 `frontend/image-optimization.json`에 기록된다.

## 요청한 화면 변경

- 진행 화면 상단에 현재 단계와 다섯 단계(매물 탐색·임장·가계약금·계약서·잔금·입주)를 표시한다. 단계 표시는 이동 버튼이 아니다.
- 용어 사전은 장면 관련 단어만 추리던 처리를 제거했다. 모든 장면에서 같은 순서의 37개 용어를 표시하며, 사용자가 검색할 때만 필터링한다.
- 등기부 미니게임과 계산기를 제거했다. 잔금 시점 선택 다음은 마지막 정리 장면이다. 일반 시나리오의 소유자·등기부 확인 내용은 유지한다.
- 계약 방식 카드에서 설명 팝업을 연다. ‘확인하고 집 고르기’만 집 유형 선택으로 진행하며, 취소·닫기·Escape는 계약 방식 화면에 남는다. 취소한 계약 방식은 적용하지 않는다. 별도의 튜토리얼 페이지는 제거했다.
- 임장 지점의 팝업에 확인 이유·확인 방법·양호한 상태·주의 신호를 표시한다. 기존 시나리오의 방법과 이상 신호를 그대로 사용하고 설명을 보강했다. ‘확인’을 눌러야 체크되며, 닫기만 해서는 체크되지 않는다.
- 추가 확인 목록은 항목의 설명을 열고 확인해도 유지된다. 선택한 항목을 확인한 뒤 목록으로 초점을 돌려 다음 항목을 계속 고를 수 있다.
- 하단에는 최근 확인한 항목과 남은 개수를 표시한다. 모든 항목 확인 후 ‘임장 마치기’를 누르면 ‘완료됐습니다.’만 표시한다.
- 임장 팁에는 ‘내 선택’ 문구와 ‘다시 선택’을 제거하고 ‘다음’만 남겼다.
- 엔딩 리뷰의 ‘이 단계 다시 보기’를 제거했다. 단계별 리뷰 내용 열람은 유지한다.

## 검증

- 자동 검사 54개 통과. 11개 계약·집 조합의 정답·오답 수정·혼합 경로 33개가 미니게임 없이 엔딩에 도달한다.
- 모든 임장 지점에 확인 이유와 양호한 상태가 있으며, 원문 확인 방법과 이상 신호가 유지되는지 검사했다.
- 빌드·린트 통과.
- 배포용 빌드를 로컬 브라우저에서 확인했다. 계약 팝업의 취소·닫기·확인, 전세 원룸 임장 13곳, 확인 전후 체크 변화, 추가 목록 유지, 완료 문구, 임장 팁의 단일 버튼을 검증했다.
- 두 장면의 사전 목록이 37개로 순서까지 동일함을 확인했다. 1·2단계 표시와 모바일 임장 안내 배치를 확인했다.
- 브라우저에서 실제 선택된 사진 주소가 작은 WebP 사본인 것을 확인했고, 압축된 문의 사진과 방 사진도 시각적으로 확인했다.
- 최종 빌드의 이미지 44개가 모두 정상 응답하며 파일 크기와 일치함을 확인했다. 서비스 번들에 원본 JPG·PNG는 남지 않는다.
- 최종 모바일 화면에서 다섯 단계 이름이 한 줄로 표시되고, 집 유형의 ‘이전’이 팝업 없이 계약 방식 선택으로 돌아오는 것을 확인했다.

Vercel의 실제 네트워크 속도와 외부 AI 서버 기능은 이번 검증에 포함하지 않았다.
